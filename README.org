** [[https://github.com/biscuitrescue/kronos][Kronos]]
[[https://img.shields.io/badge/-Zig-F7A41D?logo=zig&logoColor=black&.svg]]

*A deterministic filesystem time-machine and data debugger, written in Zig.*

Kronos treats a directory as a history you can move through, not just a current state. Files are split with Content-Defined Chunking, so a small edit changes only the chunks around it instead of the whole file. Chunks and directory snapshots are stored in a Merkle-DAG, which makes every state content-addressed, verifiable, and cheap to keep.

- *Infinite undo:* step back to any recorded state of the tree, not just the last save.
- *Data provenance:* trace which snapshot a given piece of data came from and how it changed.
- *Deterministic by design:* the same input always produces the same hashes, so histories can be compared and verified.
- *Deduplication:* identical chunks across files and versions are stored once.

The goal is a debugger for data, the way a normal debugger is for code.

** [[https://github.com/biscuitrescue/gatekeep][Gatekeep]]
[[https://img.shields.io/badge/-Rust-black?logo=rust&logoColor=white&.svg]]

*GitHub-style access control for SSH servers, built from scratch in Rust.*

Managing =authorized_keys= by hand across servers does not scale and leaves no audit trail. Gatekeep moves that into a declarative workflow: you describe who can access what in TOML, track every change in Git, and let a daemon apply it.

- *Declarative config:* access rules live in TOML files instead of ad-hoc edits on each host.
- *Git-backed history:* every grant and revocation is a commit, so changes are reviewable and reversible.
- *Sync daemon:* a secure daemon keeps servers in line with the repository.
- *Privilege separation:* designed around the idea that a daemon touching auth files should have as little power as possible.

** [[https://github.com/biscuitrescue/drag][drag]]
[[https://img.shields.io/badge/-C++-blue?logo=c%2B%2B&logoColor=white&.svg]] [[https://img.shields.io/badge/-Compiler-lightgrey.svg]]

*A toy compiler and interpreter with a Rust-inspired syntax, written in C++.*

drag started as a way to understand the full pipeline from source text to execution: lexing, parsing, building an AST, and evaluating or lowering it. It explores expression evaluation with a syntax borrowed from Rust, and has grown into an LLVM-targeting compiler.

- *Front end:* hand-written lexer and parser for a Rust-flavoured language.
- *Two execution paths:* interpret the AST directly, or compile it.
- *LLVM backend:* code generation through LLVM, which is also where I learn how real compilers optimise.
